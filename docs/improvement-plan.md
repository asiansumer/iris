# Iris 优化路线

更新于 2026-11-07。这份路线区分已有实现和下一步验收，不把规划写成已交付功能。当前继续使用本机 Codex 订阅与本地识别、检索；本轮不增加付费模型 API，不调整音色和 UI，也不启用云端部署。

## 1. 让长语音提速建立在保真基础上

**已有基础：** 完整录音识别、个人词表、超时回退和词表循环污染拦截已经存在。长语音分块做过旧录音对照，但仍有字词差异，保持关闭。

**待解决：** 分段成功、文字拼得通顺，不等于没有丢掉否定、数字或真实改口；最后一段推理变快，也不等于用户听见回复更快。

**做法：** 让完整识别和增量识别使用可核对的连续音频样本与一致切点；按话题评估个人词表，避免无关词表干扰普通表达。先核对原音频建立标注，再比较候选结果；不让另一个模型“改顺”句子来掩盖差异。

**验收条件：** 固定样本中的关键语义无新增错误，音频覆盖完整，超时与缺尾段能回退；真机分别记录停说、最终文字、首段音频和实际播放，报告样本量与失败回退。普通短句不能被拖慢。以上均通过才启用分块。

## 2. 验证活动记录能真正维持连续对话

**已有基础：** 游戏、故事和练习已有独立活动记录，可保存未揭晓答案、规则和情节，并在后续轮次交回 Iris；它不进入个人记忆，也不作为用户事实的证据。

**待解决：** 状态能够保存，不代表模型每次都会准确更新和遵守。错误活动格式目前不会阻断回复，因此还需要检查“承诺已选定答案、实际却未记录”等不一致。

**做法：** 对开始、推进、结束和重开活动分别验收；保留固定答案、已问问题、故事目标与未解线索。长对话和会话重建后仍按同一活动继续，切换话题时不强行续玩。

**验收条件：** 完成至少八轮的真实模型回放，覆盖会话重建、中途插话、换题、重开和纠正；答案不漂移、不迎合最后一次猜测，故事有实际进展。未公开的答案不泄露到客户端、个人记忆或 Clio 的事实依据里。

## 3. 改善意图理解和自然主动性

**已有基础：** 有待问问题的来源检查、冷却与反馈机制；新通话的简单招呼可作为分享一条有效想法的时机，直接交代任务时优先处理任务。

**待解决：** 询问一种风格不等于要求换风格，谈到困难也不等于希望被安慰。禁止几个套话词汇，还不足以保证回复贴合当前意思。

**做法：** 把询问、偏好表达和明确修改要求分开评估；优先使用用户当下的明确自述。问题和想法只在有信息价值、当前话题允许时出现；用户拒绝或转移话题后自然继续。

**验收条件：** 用多轮对照验证：不擅自替用户决定感受、不重复已知答案、不把普通招呼都变成采访；有值得分享的内容时能自然提出，没有时也能正常聊天。反馈改善应体现于后续行为，而不只是记下一条偏好。

## 4. 衡量检索是否找对依据

**已有基础：** 已接入字面与本机语义混合检索，支持起源、现状与规律等问题的排序；查询主体排序已优化，语义进程不可用时回退字面检索。

**待解决：** 找到更多记忆不等于找得更准，合成测试集上的召回率也不能代表所有真实问题的效果。

**做法：** 扩充有明确答案和来源标注的固定问题集，覆盖同义表达、无答案问题、时间不确定、已纠正信息以及支持与反对某个规律的例子。分别评估检索和最终回答，避免把生成错误误判为检索错误。

**验收条件：** 对照前几条结果的相关性、关键依据覆盖、纠错后过时依据的排除，以及耗时和回退比例；新日期不能自动推翻适用于旧场景的事实。索引重建后结果与有效档案一致，缓存不能成为第二份权威记忆。

## 5. 让记忆和人格修改可追溯、可回退

**已有基础：** 原话、整理条目、来源、版本和修订相互关联；晚到补述可以关联经历。SOUL 修改先成为候选，再经过隔离行为场景检查，不能直接把新猜测变成人格事实。

**待解决：** 少量场景通过并不保证长期相处更好，同一模型评审自己的候选也不是独立的人类验收。

**做法：** 持续扩展记忆固定验收集，检查重要信息遗漏、示例误记、跨会话补述和纠正后的反复错误；为 SOUL 增加多轮反馈与恢复旧版本的测试。模型观点保持为观点，用户觉得“有帮助”不等于确认它是真实事实。

**验收条件：** 纠正后，相关记忆、问题、活动和待分享观点不能被迟到任务重新污染；重启与换模型后仍有效。候选依据或基准过期时不能激活；不通过就保留原版本，前台聊天不承担后台验收等待。

## 6. 证明档案可以恢复，再启用异地备份

**已有基础：** 已有一致导出，以及尚待正式启用的加密备份、完整性核对和恢复演练代码。

**待解决：** 同一块硬盘上的副本不能解决整机丢失；文件成功复制、加密或上传，也不证明资料能完整恢复。

**做法：** 先在独立目录恢复，核对数据库、录音、来源、版本和修订关系；覆盖错误密钥、缺失附件和损坏文件。正式启用前确认恢复密钥独立保存，再根据实际需要选择异地存放方式。

**验收条件：** 可在与主档案隔离的环境中恢复并检索资料；失败明确报告，不发布半成品快照，不覆盖主档案。演练通过后才标记“可恢复”；外出访问、云备份和云服务器迁移分别验收，不因其中一项完成就宣称其余都可用。

## 每轮改进怎样算完成

先固定问题与对照材料，再改动并复测。分别记录“代码完成”“自动测试通过”“真机验证”“已启用”，保留失败结果与剩余限制。公开仓库只更新不含个人资料的结论；原始聊天、录音和运行档案继续留在本地。
